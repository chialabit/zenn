XKB は、デスクトップで「どのキーが何を意味するか」を決めている標準の層です。
X11でもWaylandでも同じ仕組みで動いていて、追加インストール不要です。

`Shift` や `Ctrl` が修飾キーとして振る舞うのを定めている場所でもあるんですが、
 変な特徴があって、「押した瞬間に飛ぶキー」と「押している間に立つ修飾ビット」を、別々に指定できます。

これを悪用(?)すると、任意のキーに、単押しとしての意味と、修飾キーとしての役割を持たせられる! 本当?!
二重人格はこれのことを言っています。

ただし時間軸や文脈が絡む設定はできません。デスクトップの外(TTYとか)にも影響できません。
そういうのは keyd や kanata 、QMK を使うしかなさそうです。

それでも、この分離だけで解ける問題はあります。
層を足したくないけど解決はしたい。需要ありますよね？！あると思いたい。

以下はその実例で、ANSIキーボードで 日本語入力の OFF を `Caps` に、 ON を `Caps + Space` に載せた話です。



## ANSIキーボードで無変換・変換をどうするか
ANSIキーボード派の私は変換キーをどこにするか一生悩んでいました。
`L_Alt` を無変換、`R_Alt` を変換にするのが、摩擦の少ない解として定着していたと思うんですけど、[^1]
`Alt` ってFirefoxとかでは単押しに意味があったりするし、`R_Alt` は左手からは遠すぎる(右利きさんの場合)のでペンやマウスとの併用で微妙につっかえます。
デバイスから効き手を離してホームポジションにつくまでの間に、片手だけで変換状態を触りたい…。

### トグルではなく ON / OFF を直接指定したい
1つのキーバインドでトグルする設定なら片手操作に優しいんですが、状態が保証されない欠点があります。
Aを押したら変換、Bを押したら無変換、みたいなのがいい。バインドが2つ必要です。

### Ctrl / Ctrl + Space は私の中での発明だった。けど…？！
Fcitx5 では修飾キーのリリースを1つのイベントとして設定できるので、Ctrl単押し = IME OFF。のようなことができます。
Ctrl 単押しが直接入力になり、コンビネーションが加わった `Ctrl + Space` だと変換になる、というのを試しました。これは意味論的にもリズム的にも凄くいい、わたしの中での発明だったんです。さらに `Space` はどんな言語でも単語や文節に小休止を置く役割があって、常にそこに親指が浮いています。かんぺきです！ なのに…

`Ctrl + Space` ってたしかkritaも使ってたんですよね。Photoshopも。ズームはホイールでしてたのであまり気になってなかったけど。
Blenderのアレでも、EmacsのMarkでも使われます。ANSIキーボードを使う限りはついて回るこの問題。

1年くらいつかったけど、意味の衝突を避けたくなってきました。

## Hyperキー先輩
そこで、現代のキーボードでは物理キーが失われていて誰も使っていない `Hyper` キー [^2] を見つけます。これをCapsLockあたりとすり替えてあげたらいいじゃないですか！
有望だったのですが、Fcitx5は `Hyper` 単押しをうまく拾ってくれません、というか、拾いはするんですけど解釈に問題がありそうです。他のコンビネーション系のキーは大丈夫なんですが。(のちにissueを出しました)

### issue: fcitx5内部の不整合?
Hyperがコードの中で意図的にsuperと混ぜられてるように見える…?!
https://github.com/fcitx/fcitx5/issues/1686


### keydを使えばいい？ いいえの場合があります
単押しの挙動を持ちつつ、 `+Space` での挙動も持ちたい。
keydはこれを解決しますが、ごく僅かにレイテンシが増えるし、パームリジェクションに関する既知の問題
https://github.com/rvaiya/keyd/issues/995
もあります。人により気になります。

### QMKは何でも解決してくれるけど…
QMKのようなハードウェア機能でキーの挙動を設定できるなら簡単です。でもすべてのキーボードが対応していなかったりします。推しキーボードは必ずしも新しくないです。MCU書き換えや載せ替えはチャレンジです。

## 解決: XKBで Muhenkan と Mod3 を分離すればよい
Hyperの修飾ビット（Mod3）と、単押し時に飛ぶkeysymを、切り離す。XKBはこれができるってClaudeパイセンが教えてくれた。


### xkb_symbolsを追加して:
ここの例はNixで書いていますが、 `xkb/symbols/custom` と `xkb/rules/evdev` にそれぞれ `''` 〜 `''` の中身をそのまま書けばubuntuとかでも同じ意味になります。
```nix
{ ... }:
{
  xdg.configFile = {
    "xkb/symbols/custom".text = ''
     partial modifier_keys
     xkb_symbols "capsime" {
       replace key <CAPS> {
         type[Group1] = "ONE_LEVEL",
         symbols[Group1] = [ Muhenkan ],
         actions[Group1] = [ SetMods(modifiers=Mod3) ]
       };
       modifier_map Mod3 { <CAPS> };
     };
    '';

    "xkb/rules/evdev".text = ''
      ! option = symbols
        custom:capsime = +custom(capsime)

      ! include %S/evdev
    '';
  };
}
```

### hyprlandとかで拾う:
ここの例は素の `hyprland.lua` です。よく触るので nix store 外に置いて直接編集しています。
```lua
hl.config({
  input = {
    kb_options = "custom:capsime",
  },
})
```
- 使っているWMやDEで読み替えてほしいです。定義したxkb_symbolsを引っ張ってこれるならなんでもよきです。

### fcitx5で対応してもらう:
GUI config(`$ fcitx5-configtool`)から設定して、`~/.config/fcitx5/config` が以下のようになればよきです。
```ini
[Hotkey/DeactivateKeys]
0=Muhenkan

[Hotkey/ActivateKeys]
0=Hyper+space
```
- GUIから `Hyper + Space` を設定するには2回押さないといけないです。たぶんissueに書いたことが関係してそう。手書き編集して再起動のほうがいいかも。


## 使用感
誰も使ってないキーに乗せたことで、IMEのON/OFFが他のアプリのバインドと重ならなくなりました。

- `Caps` 単押し → `Muhenkan` が飛ぶ → 直接入力になる
- `Caps + Space` → `Hyper + Space` が飛ぶ → かな漢字変換ONになる


- **既知の欠点**: Caps(Hyper)+Spaceは、既にONであっても一瞬OFFを必ず経由します。IME状態を目立つようにディスプレイしてる方は気になるかも。
- **偶然の利点**: Caps単押しがkeydownですぐOFFになる。リリース前に打ち始めてしまう誤爆が減ってむしろ好ましいです。

Capsは大文字固定用のトグルキーですが、あまり使わないし、なくても困りません（わたしは）。そこに漢字の意味を被せられるのも気に入っています。
Linuxで、ANSI配列で、ペン/マウスで、層を追加したくなくて、QMKもない、かな漢字ユーザーにはオススメしたいです！  狭すぎ!! もし役立つ人がいたら褒めてください。

もっといい方法を見つけたらまた記事を書きたいです。


[^1]: 日本語配列(JIS)とも近いので、US配列(ANSI)の日本語話者によくおすすめされると思います。
[^2]: `Hyper` は超古いlisp機械(なにそれ)に実在した物理キーが由来で、`Super` や `Meta` の親類。X11がその修飾子を引き継いだので、XKBにはいまも `Hyper` の席があるそうです。一方、mac界隈では修飾キー全部押しをHyperと呼ぶ慣習があって、物理キーのことではないです。Hyperさんの人格は複雑。
